# Схема и правила разметки

Excel — главный рабочий файл. Не редактируйте CSV как независимый источник: `refresh` перезаписывает их из книги. Исходные названия девяти листов сохранены; «Меню - предыдущий сбор» теперь содержит исходные и новые наблюдения, разделяемые `source_status` и `checked_at`. Добавлены «Справочник вкусов» и «Источники». Сводка пересчитывается Python и содержит готовые числа без зависимости от кэша формул Excel. Матрица 20 не заполняется автоматически.

## Единицы наблюдения и ключи

| Лист / CSV | Единица и ключ | Связь |
|---|---|---|
| Заведения / venues.csv | Один конкретный филиал, `venue_id` Vxxx; исходный числовой ID сохранён | Сетевая принадлежность в `chain` |
| Отзывы / reviews.csv | Одна публикация, `ID отзыва` Rxxx | `venue_id`, необязательный `ID автора*` |
| Авторы / authors.csv | Обезличенный участник одного отзыва, Pxxx | `ID отзыва`; не идентифицированный уникальный человек |
| Упоминания вкусов / mentions.csv | Один вкус или общая группа в одном отзыве, `ID` Mxxx | `ID отзыва`, `venue_id` |
| Меню - предыдущий сбор / menu.csv | Одна позиция меню при проверке, `menu_id` Nxxx | `venue_id`, URL и дата |
| Справочник вкусов / flavors.csv | Одно нормализованное название | `normalized_flavor` |
| Источники / sources.csv | Одно обращение для конкретной цели | `source_id` Sxxx, партия, URL, дата |

Разные филиалы не объединяются. Старый Room 13 в Голицын Лофте — V043, нынешний на Маяковского — V006. «Культура» на Некрасова 48 — V024; филиал на Ломоносова не собирался. Два описания вероятно одного визита в «Старые кони» связаны `event_group`, но не удалены как точный текстовый дубль.

## Проверка источников

`verified` — найден соответствующий опубликованный текст/видимый фрагмент, имеется URL, локатор и дата проверки. `pending` — не перепроверен; `unavailable` — доступ не получен; `not_found` — страница доступна, нужная запись не найдена; `ambiguous` — сопоставление неоднозначно; `contradicted` — источник противоречит записи; `secondary_only` — найдено только во вторичной перепубликации. В основную сводку входят только `verified`, без `duplicate_of`.

`link_type`: `direct` — конкретный отзыв, `list` — страница списка, `repost` — вторичная публикация. `source_locator` содержит показанную дату и отличительные детали, а не имя или профиль. Если публичный ID не виден, `platform_review_id` пуст. Ссылка на список никогда не выдаётся за прямую ссылку. `text_completeness` отличает полный прочитанный доступный текст от `visible_excerpt`. Проверка источника не доказывает реальность визита.

`operating_status`: open / closed / temporarily_closed / unknown. Это статус по доступной карточке, а не результат звонка или визита. Для актуального среза используйте `sample_current=yes`; закрытые и неизвестные статусы исключены. `menu_status` и `tinctures_current_menu` проверяются отдельно: наличие настоек в старом отзыве не подтверждает актуальное меню. Непрочитанная ссылка на меню имеет `menu_status=not_checked`.

`platform_verification=not_passed` сохраняет предупреждение Restoclub. `bias_flag=formulaic_language` отмечает повторяющиеся формулировки, не объявляя публикацию вымышленной. Строгий срез ограничен выбранными 30 заведениями, высокой уверенностью упоминания и отсутствием этих флагов. Он содержит 143 конкретных упоминания из 84 отзывов. Это анализ чувствительности, а не доказательство независимости людей или полного отсутствия рекламы.

## Даты, пропуски и оценки

Пустая ячейка / пустое поле CSV означает отсутствие факта. Для перечислимых состояний используются unknown и «неизвестно», для ID, URL, дат, цены, объёма и оценки — пустое значение, не ноль и не «не указана». Даты с известным годом — YYYY-MM-DD. Дата обращения сохранена в `checked_at`.

`publication_date` заполняется только при доступном указании публикации; `Дата` может хранить отображаемую дату, её смысл объясняет `date_kind`. Если Яндекс показывает только день и месяц, год не подставляется: дата остаётся пустой, видимая строка хранится в локаторе. `source_updated_at` не подменяет дату публикации. Месяц посещения Tripadvisor не подменяет дату написания. Дата отзыва не доказывает актуальность меню на дату обращения.

`rating` и `rating_scale` — опубликованная оценка заведения, если она видна; общий рейтинг карточки здесь не используется. «Оценка отзыва» — тон пересказанного отзыва, не числовая оценка. Пятизвёздочный отзыв с перечнем напитков не даёт автоматически положительных оценок каждому вкусу.

## Упоминания и нормализация

`specificity`: concrete — названная позиция; category — группа вроде сливочных; general — настойки без названия; ambiguous — неясная связь слова с напитком. Только concrete с непустым `normalized_flavor` участвуют в рейтинге вкусов. Именованная «Овощная» может быть конкретной позицией с неизвестным составом; этот пробел сохранён в названии и примечании.

`sentiment`: positive, negative, mixed, neutral, mention_only, unclear. Причина оценки относится к конкретному напитку. «Приторная» может быть отрицательной характеристикой, а «сладкая» без неприятия — нейтральной. «Очень забористо» само по себе не означает «слишком остро». Ошибка подачи или плохой сервис не становятся отрицательной оценкой всех заказанных вкусов. В одном отзыве один вкус записывается один раз; суммарная оценка повторных характеристик может быть смешанной.

`confidence`: high — явная связь и устойчивое название; medium — оговорка, очевидная опечатка или неоднозначная оценка; low — название предположительное. Уверенность относится к разметке, а не к доказанной подлинности автора.

Нормализация идёт через справочник явных вариантов. Регистр, ё/е, тип тире и пробелы унифицируются только для поиска соответствия. Начальный вариант остаётся в `raw_flavor`. Синонимы, склонения и явные опечатки добавляются в `aliases`, если соответствие установлено по тексту. Неизвестный вариант требует явного `normalized_flavor` и проверки справочника; по общему ингредиенту автоматического объединения нет.

Примеры: «кокос с бананом» → «Банан — кокос»; «малина-сливки» → «Малина — сливки». «Лаймончелло» из лайма остаётся отдельным от лимончелло. Простая томатная, острая томатная и томат-бекон-чеснок различаются. Грибная без вида не становится настойкой на белых грибах. «Электрофлора» не объединена с электроцветами без первичного подтверждения состава/названия. Основа «на джине», добавочные ингредиенты и указание ликёра/биттера сохраняются в варианте продукта.

Категории: ягодная, фруктовая, цитрусовая, травяная, пряная, десертная, сливочная, другая. Для сочетаний выбирается одна предварительная категория; она не выражает пропорции рецепта. Компоненты справочника извлечены из названия/видимого сообщения, а не подтверждены производителем. Сливочная основа считается известной лишь при прямом указании сливок/сливочности; название десерта этого не доказывает. Брендированные названия не раскрываются до рецептов. `combination_preliminary` — предварительный признак сочетания/возможной необычности, не рейтинг популярности.

## Меню и сводки

Цена за 50 мл = цена × 50 / опубликованный объём, с округлением до двух знаков. Один «шот» без миллилитров не считается 40 или 50 мл. Цены сетов не делятся между вкусами. `product_type` сохраняет явно названный ликёр/биттер внутри раздела настоек; эти строки можно исключить при узком определении напитка. Сам факт позиции в меню не равен положительному отзыву.

Основная «Сводка вкусов» использует все проверенные конкретные упоминания, включая исторические. Положительная доля делится на число явно оценённых наблюдений; простые перечисления в знаменатель не входят. Числа уникальных отзывов, заведений и база явно оценённых показываются рядом. Для общего события вклад в оценки одного вкуса ограничивается одним событием; противоположные оценки становятся смешанными. Отдельные колонки показывают строгий текущий срез. Редкость оценивается только внутри собранной базы и её покрытия.

## Ввод новой партии

JSON имеет `batch`, `venues`, `reviews`, `menu`, `sources`, необязательные `patches` и `dictionary`. Объекты используют реальные заголовки Excel. `venues` с имеющимся venue_id обновляют карточку, без него получают новый ID. Внутри `reviews` вложенный список `mentions` создаёт связи автоматически. `author` необязателен; пустой объект создаёт обезличенного участника конкретной публикации, не новую установленную личность.

Для нового проверенного отзыва обязательны venue_id, Заведение, URL, platform, link_type, checked_at, source_status=verified, source_locator и краткий пересказ. Дату/оценку оставляйте пустой, если они не опубликованы. Упоминания содержат raw_flavor, normalized_flavor для concrete, flavor_category, specificity, sentiment, confidence, Пояснение. Прямые цитаты короткие и необязательны. Новый platform_review_id — только фактический ID, не придуманный номер.

`full_text` можно передать временно для хеширования полного реально прочитанного текста: он не записывается в Excel или CSV. Не включайте имена или профили в пересказ, локатор и хешируемый текст. Повторный импорт проверяется по ID площадки, локатору и хешу. Для межплощадочной копии сохраняйте одну каноническую публикацию и фиксируйте вторую ссылку в журнале. Автоматическое доказательство независимости всех коротких похожих отзывов невозможно.

Скрипт сначала изменяет книгу в памяти, проверяет уникальность и связи, затем атомарно сохраняет файл. Ошибки останавливают запись. Предупреждения о непроверенных исходных строках не останавливают обновление, но эти строки исключены из проверенных сводок.
