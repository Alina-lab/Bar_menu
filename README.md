# Nastoyka: экономика запуска настоечного бара в Санкт-Петербурге

**[Аналитический Notebook](assortment_economics.ipynb)** · **[Отчёт](docs/economics_report.md)** · [Draft PR №1](https://github.com/Alina-lab/Nastoyka/pull/1)

Проект отвечает на вопрос: сколько сырья и денег нужно на два вечера работы бара и что меняется, если продана только часть произведённого? Инструменты: **Python, Decimal, pandas, SQL, openpyxl, Matplotlib, Jupyter и pytest**. Отзывы и рынок — предшествующий этап; текущая экономика использует утверждённые автором рецептуры и ценовой сценарий 16.10.2026.

План: **10 вкусов × 6 л = 60 л**, 1 200 порций по 50 мл. На пятницу и субботу — по 60 порций каждого вкуса за вечер. Конкретная дата запуска не задана. Состав фиксирован: 8 основных по 250 ₽, 2 премиальные по 300 ₽. Статусы выходов: **10 оценочных / 0 измеренных**.

**Последние две строки не являются чистой прибылью.** Выручка — поступления за проданные порции; использованное сырьё — расход на производство; закупочный бюджет — платёж за целые упаковки; разница между ними остаётся в сырье. Сырьевая маржинальность не включает аренду, труд, налоги, доставку, оборудование и списания готового продукта. При неполной продаже выручка меньше, хотя все 60 л уже произведены.

## Модель и запуск

Единственные действующие источники: [ассортимент](data/economics/author_selected_menu.csv), [рецептуры и технологии](data/economics/recipes.json), [редактируемые выходы](data/economics/yields.csv), [цены и фасовки](data/economics/ingredients.csv), [план](data/economics/production_plan.json). Python не подменяет эти значения другим ассортиментом. [Результаты](data/economics/results) формируются повторно из них.

```bash
python -m pip install -r requirements.txt
python scripts/economics.py
python -m pytest -q
jupyter lab assortment_economics.ipynb
python scripts/workbook.py validate
```

Совместимая команда `python scripts/author_menu.py` запускает ту же текущую модель. Отчёт и графики обновляются вместе с CSV. Для пересборки структуры Notebook: `python -m scripts.report --notebook`; затем выполнить его сверху вниз в новом ядре. [Протокол проверок](docs/validation.md).

## Ограничения и история

Все выходы — оценки; конечная крепость не равна автоматически 40%. C12: 14 дней — наблюдение автора, не установленный безопасный коммерческий срок. Нужны надлежащие условия хранения и проверка требований пищевой безопасности. Продажи — сценарии, не подтверждённые посещения или спрос; продуктовые эксперименты не проводились.

Сохранены первичная книга, старые CSV отзывов, ID и нормализация: 368 отзывов и 468 упоминаний. [Методика сбора](docs/methodology.md) и [отчёт сбора](docs/collection_report.md) неизменны. [История A/B/C/B2 и этапов 1–3](data/economics/history/README.md) отделена от действующей модели: старые цены, расчёт по 1 л и прошлые графики доступны в архиве и Git-коммитах. [Текущая методика экономики](docs/economics_methodology.md).

Работа ведётся в `analysis/menu-economics`; PR №1 остаётся черновиком. Слияние в main без отдельного разрешения автора запрещено.
